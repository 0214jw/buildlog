# BuildLog 기능 동작 설명서

## 1. 문서 기준

이 문서는 [PRD.md](PRD.md)를 기준으로 사용자의 행동과 처리 결과를 설명합니다. 새 기능은 추가하지 않습니다. PRD에 없는 세부 규칙은 **확인 필요**로 남깁니다.

각 기능의 ‘확인 방법’은 개발 후 사용할 점검 항목입니다. 지금 기능을 개발하거나 점검을 실행했다는 뜻은 아닙니다.

### 공통으로 적용할 기준

- 자신의 기록을 관리하려면 로그인해야 합니다.
- 공부 기록, 할 일, 오류 기록은 처음 만들 때 비공개가 기본입니다.
- 비공개 기록은 작성자만 볼 수 있습니다. 공개 기록도 로그인하지 않은 사람은 볼 수 없습니다.
- 다른 사용자는 공개 기록을 읽을 수 있지만 기록 자체를 수정하거나 삭제할 수 없습니다.
- 입력 조건에 맞지 않는 내용은 저장을 완료한 것으로 처리하지 않습니다. 무엇을 고쳐야 하는지 사용자가 알 수 있어야 합니다.
- 저장·수정·삭제에 실패하면 성공한 것으로 표시하지 않고 실패 사실을 알립니다. 목록이나 기록을 불러오는 데 실패한 경우에도 빈 결과와 실패를 구분할 수 있어야 합니다.
- 실패 안내의 정확한 문구와 위치, 입력한 내용의 유지 방식, 다시 시도하는 방식은 **확인 필요**입니다.
- 권한이 없는 사용자의 조회·수정·삭제는 허용하지 않습니다. 안내 화면이나 이동할 화면은 **확인 필요**입니다. 주소를 직접 입력해 접근해도 같은 권한을 적용해야 합니다.
- 글자 수를 셀 때 공백을 어떻게 처리하는지는 **확인 필요**입니다. 아래의 길이 기준은 PRD의 숫자를 그대로 사용합니다.

## 2. 회원가입

### 사용자가 입력하거나 누르는 것

이메일, 비밀번호, 닉네임을 입력하고 회원가입을 요청합니다.

| 입력 항목 | PRD에서 정한 조건 | 확인 필요 |
| --- | --- | --- |
| 이메일 | 회원가입과 로그인에 사용 | 이메일 형식 검사 기준, 중복 가입 허용 여부 |
| 비밀번호 | 로그인에 사용 | 최소·최대 길이와 사용할 수 있는 문자 등 비밀번호 조건 |
| 닉네임 | 다른 사용자와 중복 불가 | 길이, 사용할 수 있는 문자, 대소문자·공백을 중복 판단에 반영하는 방식 |

### 정상 처리 결과

입력한 정보로 회원 계정이 만들어집니다. 닉네임은 다른 회원과 겹치지 않아야 합니다. 가입 완료를 알 수 있어야 하며, 가입 직후 자동 로그인 여부와 이동할 화면은 **확인 필요**입니다.

### 잘못 입력하거나 실패한 경우

필요한 정보가 빠졌거나 닉네임이 중복되면 가입을 완료하지 않고 고칠 항목을 알립니다. 이메일과 비밀번호의 구체적인 거절 기준은 위의 확인 사항을 결정한 뒤 적용합니다. 저장 실패 시 가입 성공으로 표시하지 않습니다.

### 누가 사용할 수 있나요?

가입하려는 사람이 사용합니다. 이미 로그인한 사용자가 가입 화면을 열었을 때의 처리는 **확인 필요**입니다. 회원가입으로 다른 사람의 비공개 기록을 볼 권한이 생기지 않습니다.

### 나중에 확인하는 방법

- 필요한 정보를 입력하면 계정이 만들어지고 해당 정보로 로그인할 수 있는지 확인합니다.
- 같은 닉네임으로 두 계정을 만들 수 없는지 확인합니다.
- 필수 항목 누락과 저장 실패를 가입 성공으로 표시하지 않는지 확인합니다.
- 이메일 확인과 비밀번호 찾기 기능이 이번 범위에 들어가지 않았는지 확인합니다.

## 3. 로그인

### 사용자가 입력하거나 누르는 것

가입한 이메일과 비밀번호를 입력하고 로그인을 요청합니다. 닉네임으로 로그인하는 기능은 PRD에 없습니다.

### 정상 처리 결과

계정 정보가 맞으면 로그인한 상태가 되어 자신의 기록을 만들고 관리할 수 있습니다. 로그인 자체가 새로운 기록을 만들지는 않습니다. 로그인 직후 이동할 화면과 로그인 유지 시간은 **확인 필요**입니다.

### 잘못 입력하거나 실패한 경우

이메일이나 비밀번호가 빠지거나 계정 정보가 맞지 않으면 로그인되지 않습니다. 오류나 처리 실패를 알립니다. 계정이 없는 경우와 비밀번호가 틀린 경우의 안내 문구는 **확인 필요**입니다.

### 누가 사용할 수 있나요?

가입한 사용자가 자신의 계정 정보로 로그인합니다. 로그인해도 다른 사용자의 비공개 기록은 볼 수 없습니다.

### 나중에 확인하는 방법

- 올바른 이메일과 비밀번호로 로그인되는지 확인합니다.
- 비밀번호가 틀리거나 입력이 빠지면 로그인되지 않는지 확인합니다.
- 사용자 두 명을 준비해 로그인한 계정에 따라 자신의 기록만 관리할 수 있는지 확인합니다.
- 로그인하지 않은 상태에서는 공개 기록도 볼 수 없는지 확인합니다.

## 4. 닉네임 변경

### 사용자가 입력하거나 누르는 것

계정 설정에서 새 닉네임을 입력하고 변경을 요청합니다.

### 정상 처리 결과

자신의 계정에 새 닉네임이 저장되고 변경된 닉네임을 확인할 수 있습니다. 과거 기록과 댓글에 표시된 닉네임도 함께 바뀌는지는 **확인 필요**입니다.

### 잘못 입력하거나 실패한 경우

다른 사용자가 쓰는 닉네임이면 변경할 수 없습니다. 빈 입력이나 결정된 입력 조건에 맞지 않는 값도 변경 완료로 처리하지 않습니다. 실패하면 변경 실패를 알립니다.

### 누가 사용할 수 있나요?

로그인한 사용자가 자신의 닉네임만 변경합니다. 다른 사용자의 닉네임은 변경할 수 없습니다.

### 나중에 확인하는 방법

새 닉네임이 저장되는지, 다른 사용자의 닉네임으로 바꿀 수 없는지, 다른 계정의 닉네임을 변경할 수 없는지 확인합니다. 변경 실패를 성공으로 보여주지 않는지도 확인합니다.

## 5. 공부 기록

### 5.1. 작성

| 구분 | 동작 설명 |
| --- | --- |
| 입력·행동 | 제목 1~100자, 내용 1~5,000자를 입력하고 공개 여부를 정해 저장합니다. 공개 여부의 기본값은 비공개입니다. |
| 정상 결과 | 제목, 내용, 공개 여부와 작성 날짜·시간이 저장됩니다. 작성 날짜·시간은 자동으로 저장하며 사용자가 입력하지 않습니다. 저장한 기록을 다시 볼 수 있어야 합니다. 저장 직후 이동할 화면은 확인 필요입니다. |
| 잘못된 입력·실패 | 제목이나 내용이 비어 있거나 길이 범위를 벗어나면 저장하지 않고 해당 항목을 알립니다. 저장 실패를 성공으로 표시하지 않습니다. |
| 권한 | 로그인한 사용자가 자신의 기록을 만듭니다. 비공개일 때는 본인만, 공개일 때는 로그인한 다른 사용자도 볼 수 있습니다. |
| 확인 방법 | 제목 1자·100자, 내용 1자·5,000자는 저장되고, 빈 값과 각각 101자·5,001자는 거절되는지 확인합니다. 작성 시간 자동 저장, 기본 비공개, 나중에 다시 읽기도 확인합니다. |

### 5.2. 목록과 자세히 읽기

| 구분 | 동작 설명 |
| --- | --- |
| 입력·행동 | 내 공부 기록 목록을 열고 읽을 기록을 선택합니다. |
| 정상 결과 | 내가 작성한 기록을 최근에 작성한 순서로 봅니다. 선택한 기록의 제목과 내용을 자세히 읽습니다. 이 동작은 기록을 변경하지 않습니다. |
| 잘못된 입력·실패 | 목록을 불러오지 못하거나 선택한 기록이 없으면 그 사실을 알립니다. 다른 사람의 비공개 기록은 보여주지 않습니다. |
| 권한 | 내 목록은 본인의 기록을 확인하는 화면입니다. 다른 사람의 공개 공부 기록은 로그인 후 공개 기록에서 볼 수 있습니다. |
| 확인 방법 | 작성 시점이 다른 기록 여러 개의 순서와 상세 내용을 확인합니다. 다른 사람의 비공개 기록이 목록이나 직접 접근으로 보이지 않는지 확인합니다. |

### 5.3. 수정과 삭제

| 구분 | 동작 설명 |
| --- | --- |
| 입력·행동 | 자신의 기록에서 수정을 선택해 제목·내용·공개 여부를 바꾸고 저장하거나 삭제를 요청합니다. |
| 정상 결과 | 수정한 값이 저장되어 다시 열어도 반영됩니다. 삭제가 완료되면 해당 기록을 목록이나 읽기 화면에서 더 이상 볼 수 없습니다. 공개 여부 변경은 8절도 따릅니다. |
| 잘못된 입력·실패 | 수정에도 작성과 같은 길이 조건을 적용합니다. 조건 위반이나 처리 실패를 성공으로 표시하지 않습니다. 없는 기록이나 다른 사람의 기록은 수정·삭제할 수 없습니다. |
| 권한 | 기록 작성자만 수정·삭제할 수 있습니다. 공개 여부와 관계없이 동일합니다. |
| 확인 방법 | 수정한 내용이 유지되는지, 잘못된 길이는 거절되는지, 삭제 후 보이지 않는지, 다른 사용자가 수정·삭제할 수 없는지 확인합니다. |

삭제 전 재확인 방식과 기록 삭제 시 댓글·좋아요·신고의 처리 방식은 **확인 필요**입니다. 수정할 때 작성 날짜·시간을 어떻게 다룰지도 **확인 필요**입니다.

## 6. 할 일

### 6.1. 작성과 수정

| 구분 | 동작 설명 |
| --- | --- |
| 입력·행동 | 제목 1~100자와 공개 여부를 입력해 저장합니다. 기존 할 일에서는 제목이나 공개 여부를 바꾸고 저장합니다. 본문·마감일·중요도를 입력하는 기능은 포함하지 않습니다. |
| 정상 결과 | 제목, 완료 여부, 공개 여부를 저장하고 목록에서 확인합니다. 공개 여부의 기본값은 비공개입니다. 새 할 일의 최초 완료 상태와 작성 화면에서 바로 완료를 선택할 수 있는지는 확인 필요입니다. |
| 잘못된 입력·실패 | 제목이 비었거나 100자를 넘으면 저장하지 않고 이유를 알립니다. 처리 실패를 성공으로 표시하지 않습니다. |
| 권한 | 로그인한 사용자가 자신의 할 일을 작성·수정합니다. 다른 사용자는 공개된 할 일만 읽을 수 있습니다. |
| 확인 방법 | 제목 1자·100자가 저장되고 빈 제목·101자가 거절되는지, 수정 결과가 유지되는지, 기본 비공개인지, 다른 계정이 수정할 수 없는지 확인합니다. |

### 6.2. 완료 여부 변경

| 구분 | 동작 설명 |
| --- | --- |
| 입력·행동 | 자신의 할 일의 완료 표시를 눌러 미완료 또는 완료로 바꿉니다. |
| 정상 결과 | 완료 여부가 저장되고 화면 표시와 상태별 목록에 반영됩니다. 완료로 체크할 때 완료 날짜와 시간이 자동 저장됩니다. |
| 잘못된 입력·실패 | 상태 변경에 실패하면 완료 여부가 바뀌었다고 표시하지 않고 실패를 알립니다. 다른 사람의 상태는 바꿀 수 없습니다. |
| 권한 | 할 일 작성자만 바꿀 수 있습니다. |
| 확인 방법 | 완료 체크 후 다시 열어도 상태가 유지되고 완료 시간이 저장되는지 확인합니다. 미완료로 변경할 수 있는지와 상태별 목록 반영도 확인합니다. |

미완료로 되돌릴 때 완료 날짜·시간을 지울지, 다시 완료하면 시간을 새로 저장할지는 **확인 필요**입니다.

### 6.3. 목록과 상태별 보기

| 구분 | 동작 설명 |
| --- | --- |
| 입력·행동 | 내 할 일 목록을 열고 전체·남은 일·완료한 일 중 하나를 선택합니다. |
| 정상 결과 | 전체는 모든 내 할 일, 남은 일은 미완료, 완료한 일은 완료 항목을 보여줍니다. 미완료가 먼저 나오고 같은 상태에서는 최근에 작성한 항목부터 보여줍니다. 조회 자체는 저장된 상태를 바꾸지 않습니다. |
| 잘못된 입력·실패 | 목록을 불러오는 데 실패하면 실패를 알립니다. 결과가 없는 것과 조회 실패를 구분합니다. |
| 권한 | 본인의 할 일 목록을 봅니다. 다른 사람의 공개 할 일은 공개 기록 화면에서 봅니다. |
| 확인 방법 | 작성 시점과 완료 상태가 다른 항목을 준비해 세 가지 보기의 대상과 순서가 맞는지 확인합니다. |

### 6.4. 삭제

| 구분 | 동작 설명 |
| --- | --- |
| 입력·행동 | 자신의 할 일에서 삭제를 요청합니다. |
| 정상 결과 | 삭제된 할 일은 내 목록과 공개 기록에서 더 이상 보이지 않습니다. |
| 잘못된 입력·실패 | 없는 항목이나 권한 없는 항목은 삭제할 수 없습니다. 삭제 실패를 성공으로 표시하지 않습니다. |
| 권한 | 작성자만 삭제할 수 있습니다. |
| 확인 방법 | 미완료·완료 항목을 각각 삭제해 목록에서 사라지는지, 다른 계정이 삭제할 수 없는지 확인합니다. |

## 7. 오류 기록

### 7.1. 작성

| 입력 항목 | 조건 |
| --- | --- |
| 오류 제목 | 1~100자 |
| 오류 내용 | 1~5,000자 |
| 해결 방법 | 미해결일 때 비워둘 수 있음. 입력하면 1~5,000자 |
| 해결 여부 | 미해결 또는 해결. 해결 상태에는 해결 방법이 반드시 필요 |
| 공개 여부 | 기본 비공개, 공개로 변경 가능 |
| 해결 날짜와 시간 | 해결 상태로 바꿀 때 자동 저장 |

- **입력·행동:** 오류 제목과 내용을 입력하고 저장합니다. 해결하지 못했다면 해결 방법 없이 미해결로 저장할 수 있습니다.
- **정상 결과:** 입력한 오류와 해결 상태, 공개 여부가 저장됩니다. 나중에 다시 열어 볼 수 있습니다. 작성 시 이미 해결 상태로 저장할 수 있는지는 **확인 필요**입니다.
- **잘못된 입력·실패:** 제목·내용 누락, 길이 범위 초과, 해결 방법 없는 해결 상태는 저장하지 않습니다. 미해결이라도 해결 방법을 입력했다면 최대 5,000자 조건을 적용합니다. 실패를 성공으로 표시하지 않습니다.

- **확인 방법:** 제목 1자·100자와 내용 1자·5,000자의 저장, 빈 제목·내용과 101자·5,001자의 거절을 확인합니다. 해결 방법 없는 미해결 저장과 기본 비공개도 확인합니다.

## 8. 공개·비공개 변경

### 사용자가 입력하거나 누르는 것

작성자가 자신의 공부 기록, 할 일, 오류 기록의 공개 여부를 선택하고 저장합니다.

### 정상 처리 결과

선택한 공개 여부가 저장됩니다. 비공개는 본인만 보고, 공개는 로그인한 다른 사용자도 볼 수 있습니다. 비공개로 바꾼 기록은 다른 사용자의 공개 목록·검색·읽기에서 볼 수 없어야 합니다. 공개로 바꾸면 공개 기록에서 확인할 수 있습니다.

### 잘못 입력하거나 실패한 경우

다른 사람의 공개 여부는 바꿀 수 없습니다. 처리 실패를 변경 완료로 표시하지 않습니다. 로그인하지 않은 사람에게 공개 내용을 보여주지 않습니다.

### 누가 사용할 수 있나요?

공개 여부는 기록 작성자만 바꿉니다. 다른 사용자의 읽기 권한이 생겨도 수정·삭제 권한은 생기지 않습니다.

### 나중에 확인하는 방법

세 종류 모두 처음에는 비공개인지 확인합니다. 작성자, 다른 로그인 사용자, 비로그인 상태로 각각 목록·검색·직접 접근을 확인합니다. 공개 후에는 로그인한 다른 사람이 읽을 수 있고 다시 비공개로 바꾸면 읽을 수 없어야 합니다.

공개 기록을 비공개로 바꿀 때 기존 댓글·좋아요를 어떻게 보관하고 다시 공개할 때 보여줄지는 **확인 필요**입니다.

## 10. 검색

### 입력 대상별 조건

| 검색 위치 | 입력·행동 | 검색할 기록과 항목 |
| --- | --- | --- |
| 내 공부 기록 | 검색어를 입력하고 검색 요청 | 본인의 공부 기록 제목과 내용 |
| 내 오류 기록 | 검색어를 입력하고 검색 요청 | 본인의 오류 제목과 오류 내용. 해결 방법까지 검색할지는 확인 필요 |
| 공개 공부 기록 | 검색어를 입력하고 검색 요청 | 공개 공부 기록. 검색할 항목은 확인 필요 |
| 공개 할 일 | 검색어를 입력하고 검색 요청 | 공개 할 일. 검색할 항목은 확인 필요 |
| 공개 오류 기록 | 검색어를 입력하고 검색 요청 | 공개 오류 기록. 검색할 항목과 해결 방법 포함 여부는 확인 필요 |

내 할 일 검색은 이번 버전에 포함하지 않습니다. 공개 할 일 검색과 구분합니다.

### 정상 처리 결과

해당 범위에서 검색어에 맞는 기록을 보여주고 선택한 기록을 읽을 수 있습니다. 내 검색은 다른 사람의 기록을 포함하지 않고, 공개 검색은 비공개 기록을 포함하지 않습니다. 검색은 원본 기록을 수정하지 않습니다. 일치하는 기록이 없으면 결과가 없음을 알 수 있어야 합니다.

### 잘못 입력하거나 실패한 경우

검색 처리에 실패하면 결과가 없다고만 보여주지 않고 실패를 알립니다. 빈 검색어 처리, 검색어 길이 제한, 일부 단어 일치 방식과 대소문자 구분은 **확인 필요**입니다.

### 누가 사용할 수 있나요?

내 기록 검색은 로그인한 본인만 사용합니다. 공개 검색도 로그인한 사용자만 사용합니다. 검색 결과를 통해 비공개 기록을 볼 수 없어야 합니다.

### 나중에 확인하는 방법

- 내 공부·오류 기록에서 제목에만 있는 단어와 내용에만 있는 단어로 각각 검색합니다.
- 같은 단어가 다른 사용자의 비공개 기록에도 있어도 노출되지 않는지 확인합니다.
- 공개된 세 종류를 각각 검색하고 결과가 현재 공개 상태인 기록만 포함하는지 확인합니다.
- 검색 결과 없음과 조회 실패가 구분되는지 확인합니다.
- 확인 필요인 검색 규칙은 결정한 뒤 그 조건으로 점검합니다.

| 정상 결과 | 처음 누르면 해당 사용자와 기록에 대한 좋아요가 저장됩니다. 같은 사용자는 같은 기록에 하나만 남길 수 있습니다. 다시 누르면 취소되어 누르지 않은 상태가 됩니다. 본인의 좋아요 상태를 확인할 수 있어야 합니다. |
| 잘못된 입력·실패 | 공개 할 일이나 접근할 수 없는 기록에는 좋아요를 남길 수 없습니다. 처리 실패를 성공으로 표시하지 않습니다. |
| 권한 | 로그인하고 해당 공개 기록을 볼 수 있는 사용자가 자신의 좋아요를 등록·취소합니다. 다른 사람의 좋아요를 취소할 수 없습니다. 자신의 기록에도 누를 수 있는지는 확인 필요입니다. |
| 확인 방법 | 누르기·다시 누르기로 등록과 취소가 되는지, 반복 요청으로 같은 사용자의 좋아요가 중복 저장되지 않는지 확인합니다. 사용자 두 명의 좋아요가 각각 관리되고 다른 사람의 것을 취소할 수 없는지 확인합니다. |

전체 좋아요 수와 누른 사람의 목록을 화면에 표시할지는 **확인 필요**입니다.

## 13. 신고

### 사용자가 입력하거나 누르는 것

로그인한 사용자가 공개 기록이나 댓글에서 신고를 요청합니다. 공개 기록에는 공부 기록, 할 일, 오류 기록이 포함됩니다. 댓글 신고 대상은 댓글 기능이 있는 공개 공부·오류 기록의 댓글입니다.

신고 사유를 선택하거나 내용을 입력해야 하는지, 그 항목과 길이 조건은 **확인 필요**입니다.

### 정상 처리 결과

신고한 내용이 운영자가 확인할 수 있도록 저장됩니다. 신고 요청이 접수되었음을 알 수 있어야 합니다. 신고되었다는 이유만으로 대상 기록이나 댓글을 자동 삭제하지 않습니다.

### 잘못 입력하거나 실패한 경우

비로그인 상태에서는 신고할 수 없습니다. 없는 대상이나 접근할 수 없는 비공개 기록을 신고하는 요청을 정상 접수로 처리하지 않습니다. 저장 실패 시 접수 완료로 표시하지 않습니다. 중복 신고 처리와 신고 내용의 입력 오류 기준은 **확인 필요**입니다.

### 누가 보거나 관리할 수 있나요?

로그인한 사용자가 신고하고 운영자가 신고 내용을 확인합니다. 운영자가 확인하는 화면·방법과 확인 이후의 처리 권한은 **확인 필요**입니다. 일반 사용자의 신고 내역 조회·수정·삭제는 PRD에 정해져 있지 않으므로 기능으로 추가하지 않습니다. 신고 내용 공개 범위와 본인 기록·댓글의 신고 허용 여부도 **확인 필요**입니다.

### 나중에 확인하는 방법

- 로그인한 사용자가 공개 공부 기록·할 일·오류 기록과 공개 댓글을 각각 신고할 수 있는지 확인합니다.
- 신고 내용이 저장되어 운영자가 확인할 수 있는지 확인합니다. 확인 방법은 결정 후 점검합니다.
- 신고 후에도 대상 기록·댓글이 자동 삭제되지 않는지 확인합니다.
- 비로그인 신고와 저장 실패가 접수 완료로 표시되지 않는지 확인합니다.

## 14. 홈, 화면 이동과 휴대폰 사용

| 구분 | 동작 설명 |
| --- | --- |
| 입력·행동 | 로그인한 사용자가 내 기록 홈에서 공부 기록·할 일·오류 기록 메뉴를 누르거나 계정 설정에서 닉네임 변경을 선택합니다. 컴퓨터와 휴대폰에서 같은 주요 기능을 사용합니다. |
| 정상 결과 | 선택한 기능으로 이동하고 자신의 핵심 기록을 읽기 쉬운 카드로 확인합니다. 밝은 배경을 사용하고 메뉴 위치와 이름을 분명하게 표시합니다. 화면 크기에 맞게 내용이 정리됩니다. 화면을 옮기거나 크기를 바꾸는 것만으로 기록이 변경되지는 않습니다. |
| 잘못된 입력·실패 | 화면이나 기록을 불러오지 못하면 실패를 알립니다. 휴대폰에서도 입력 조건과 권한은 동일하게 적용합니다. |
| 권한 | 내 홈과 계정 설정은 로그인한 본인을 위한 화면입니다. 화면 크기가 달라도 다른 사용자의 비공개 기록을 볼 수 없습니다. |
| 확인 방법 | 컴퓨터와 휴대폰에서 가입·로그인·닉네임 변경·기록 작성과 읽기·수정·삭제·상태 변경·검색·공개 설정·댓글·좋아요·신고를 사용할 수 있는지 확인합니다. 글과 버튼을 읽고 누를 수 있는지도 확인합니다. |

홈에 표시할 핵심 기록의 선정 방식과 개수, 정확한 색상·배치·버튼 문구는 **확인 필요**입니다. 새로운 통계나 대시보드 기능을 추가한다는 뜻은 아닙니다.

## 15. 이번 버전에 포함하지 않는 것과 제작 범위

- 이메일 확인
- 비밀번호 찾기
- 할 일 마감일과 중요도
- 내 할 일 검색
- 댓글 답글

PRD의 기술 선택은 프론트엔드에 React·HTML·CSS·JavaScript, 백엔드에 Python·FastAPI, 실제 서비스 데이터베이스에 Supabase입니다. 로컬 개발·테스트에서는 먼저 SQLite3를 사용합니다. React 화면은 FastAPI에 저장·조회 등을 요청하며, 사용 권한은 FastAPI에서도 검사합니다. 정확한 버전과 연결 도구는 개발 시작 시 호환성을 확인하여 결정합니다.

SQLite3로 개발할 때도 실제 서비스와 같은 입력 조건과 권한 규칙을 적용합니다. 이후 Supabase 연결 환경에서 데이터 저장·조회·검색·상태 변경·중복 방지·권한을 다시 확인해야 합니다. 로컬 테스트 데이터가 실제 DB로 자동 복사된다고 가정하지 않습니다. 테스트 데이터 이전이 필요한지는 확인 필요입니다.

Supabase는 DB로 사용하지만 Supabase Auth 사용 여부는 아직 정하지 않았습니다. FastAPI가 직접 회원가입·로그인을 처리할지 Supabase Auth를 사용할지 확인 필요입니다. 선택한 인증 방식은 로컬 SQLite3 테스트 방법에도 반영해야 합니다. Supabase Auth를 선택하더라도 SQLite3가 그 인증 서비스를 대신한다고 가정하지 않습니다.

운영자 신고 확인은 Django 관리자 화면을 사용하지 않습니다. FastAPI의 운영자 권한 검사와 함께 어떤 방법으로 신고를 확인할지는 13절의 확인 필요 항목으로 남깁니다. 별도의 신고 처리 상태 등 새로운 제품 기능은 추가하지 않습니다.

이 문서 변경 단계에서는 코드 작성, 설치, Supabase 프로젝트 생성·연결을 진행하지 않습니다.
